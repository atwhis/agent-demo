## Context

动机与交付范围见 proposal.md。当前 ChatService 创建 conversationId 后未传给模型网关；网关只使用当前 user message。ToolResultRecorder 用 traceId 映射单个 ToolResult，结束时直接清理，无法保留同轮多次调用。前端只在 done 后保存 conversationId。

本项横跨请求生命周期、模型消息、工具执行、图表协议和页面状态，需要先约定共享数据边界。技术栈继续使用 Java 21、Spring AI 2.0.0 和现有 WebFlux SSE，不增加中间件。

## Goals / Non-Goals

**Goals:**
- 将消息窗口、轮次执行证据和活动请求分开管理，保证取消与清理不会留下可复用的半轮状态。
- 对第二项公开稳定的会话、轮次与 SSE 接缝，同时使本项无需 RAG 也可独立验收。

**Non-Goals:**
- 不预建意图分类器、知识检索接口或通用 Agent 运行框架。
- 不持久化消息、引入摘要／画像／用户认证，也不建设调用记录页面。

## Decisions

### 1. 使用内存消息窗口，显式控制提交

复用 Spring AI MessageWindowChatMemory 与内存 repository，窗口最多 20 条普通 user／assistant 消息。网关显式读取历史并追加当前问题，只有整个业务轮次成功后才成对写入；不让自动写入 Advisor 抢先保存失败或取消的回答。

消息中不保存 ToolResponse、中间图表意图或原始业务表格执行证据。系统提示词每轮重新构建；切换 provider 仍读取同一窗口。上下文超预算时以完整轮次进一步缩小窗口，所选 ChatModel 的历史和当前消息只各传一次。

替代方案是前端提交全部历史或由 Advisor 自动写入；前者让服务端无法统一窗口，后者增加取消与成功判定的耦合，因此采用服务端显式提交。

### 2. 标识与状态契约

| 对象 | 契约 |
|---|---|
| conversationId | 会话标识；未提供时在服务端生成，重启后旧 ID 可重新成为空会话 |
| turnId | 每次已接纳请求的唯一标识，traceId 直接使用同值，不重复产生一套轮次 ID |
| callId | 每次工具执行的唯一标识，不能用工具名代替 |
| 轮次状态 | RUNNING → COMPLETED／FAILED／CANCELLED |
| 调用状态 | RUNNING → SUCCESS／ERROR／CANCELLED，成功空集为 SUCCESS 且 rowCount=0 |

同一会话只允许一轮活动请求，使用会话范围的接纳／释放机制；不同会话不共用锁。记录在调用开始建立，在工具回调边界更新结果、时间和耗时，统一捕获成功与异常。向工具上下文传递 conversationId、turnId、callId，避免通过共享可变字段推断当前调用。

保存两种有界数据：最近 10 个成功消息对，以及最近 10 次已接纳请求的执行记录。失败和取消占执行记录窗口，不占成功消息窗口。活动记录关闭后生成只读快照；清理与迟到回调以活动轮次身份校验，禁止使用无条件 computeIfAbsent 重新建回已删除会话。

### 3. 终止、数据验证和图表来源

流订阅时接纳轮次并发出 start，随后调用模型。终止处理只执行一次：成功时提交消息与完整记录，错误／取消只保留对应执行记录，最后释放活动请求资源。清理会话时先撤销活动轮次写入资格，再移除消息与记录。

保留已有业务关键词判断，并利用上一轮销售调用和“只看／改成／按周”等明确续问表达覆盖省略业务词的追问。系统提示词要求本轮重新取数；最终成功判定查看本轮调用记录。第二项引入显式路由后，只在 SALES 下调用同一数据验证逻辑，不在本项提前实现路由分类。

销售调用失败则整轮 error；全部所需调用成功且为空时返回无数据说明。业务数据和图表只来自当前轮结构化结果。记录完成时分配递增完成序号，选取序号最大的成功非空销售调用生成唯一图表；展示意图单独读取且 NONE 继续抑制图表。ChartSpec 增加 sourceCallId，保留 sourceTool 和 1.0 版本。

### 4. API、SSE 与现有页面

- POST /api/chat/stream 保留现有请求字段。
- 接纳后首个事件为 start，数据为 `{conversationId, turnId}`；done 返回同一组标识；delta、chart、error 沿用现有含义。
- DELETE /api/conversations/{conversationId} 幂等清理，成功返回 204。
- GET /api/conversations/{conversationId}/turns/{turnId} 返回轮次及调用快照；不存在或会话不匹配返回 404。该接口用于学习调试，不增加界面。

前端收到 start 即保存标识；新会话先让旧请求失效并 abort，再发清理请求、清空消息与本地 ID。每次请求捕获本地 generation，旧事件、旧 finally 和迟到 done 均不能修改新页面状态。清理失败提示未清理成功，不假装服务端已删除。

替代方案是只清空浏览器消息；这不能清除服务端记忆，因此必须包含清理接口。无需增加会话列表或历史管理页面。

## Risks / Trade-offs

- [取消不能保证已发出的 Feign 请求立即中断] → 停止后续调度与输出，关闭轮次写入资格，丢弃迟到结果；不宣称撤销已执行查询。
- [内存消息与调用结果不是持久化历史] → 明确最近窗口、重启清空和手动清理语义；按会话分别限制消息与记录数量。
- [窗口内仍可能包含旧业务数字] → 提示词与当前轮证据守卫共同要求重新查询，覆盖省略业务词的续问用例。
- [两个变更修改同一 SSE 和网关契约] → 本项先实现和同步，第二项保留 start／done 及单图约定，仅增量扩展 sources 和路由。

## Migration Plan

1. 实现内存状态、工具记录和生命周期，使用假模型和假销售 Client 运行离线验证。
2. 同一发布中更新 SSE 与前端，运行既有销售、图表、取消和模型切换回归。
3. 验收后同步并归档本项，再开始第二项的实现；提案阶段允许两项并存。
4. 回滚时同时回退 AI 服务和前端；无数据库迁移，重启即可清空本项内存状态。
