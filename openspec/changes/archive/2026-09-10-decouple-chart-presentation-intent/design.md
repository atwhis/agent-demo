## Context

当前 `SalesTools` 负责取得可信业务数据并按 `traceId` 写入 `ToolResultRecorder`，模型完成流式回答后，`ChatService` 把记录的 `ToolResult` 交给 `ChartCompiler`。`ChartCompiler` 既负责将不同 Tool 的类型化结果转换为通用行数据，也按 Tool 名称固定选择图表类型和指标。前端只接受 `bar`、`pie`、`line` 三类声明式 ChartSpec。

## Goals / Non-Goals

**Goals:**

- 让业务 Tool 的选择只表达“查什么”，展示意图只表达“怎么画”。
- 在用户明确要求图表类型或指标时体现该意图，没有要求时保持现有默认行为。
- 保持 Tool 数据为唯一图表数据源，并继续由服务端生成受限 ChartSpec。
- 复用当前模型调用、请求 `traceId`、结果记录和 SSE 收口流程。

**Non-Goals:**

- 不允许模型输出原始图表数据、ECharts option 或 JavaScript。
- 不支持一个回答中的多个业务结果或多个图表。
- 不新增模型调用、前端图表类型或销售统计接口。
- 不根据数据规模自动推荐“最佳图表”；只有明确意图覆盖和既有默认值。

## Decisions

### 1. 用独立模型 Tool 表达展示意图

新增一个无外部副作用的展示意图 Tool，参数仅包含图表类型和可选指标。模型仍根据业务问题调用现有销售 Tool；当用户明确说“用饼图”“按销售额画柱状图”或“不要图”时，再独立调用展示意图 Tool。

两类 Tool 共享本轮 `traceId`，因此调用顺序不影响最终收口。展示 Tool 只记录意图，不读取或修改业务数据。

选择该方案是因为它复用现有 Tool Calling 循环且不增加模型请求。没有采用关键词正则，因为它无法可靠覆盖自然语言表达；没有采用第二次结构化模型调用，因为它增加延迟和费用；没有解析模型正文中的 JSON，因为这会污染用户回答并削弱安全边界。

### 2. 展示意图采用小型白名单

请求级展示意图包含：

```text
chartType = AUTO | BAR | PIE | LINE | NONE
metric    = DEFAULT | 销售额 | 销售数量 | 购买数量 | 订单数 | 销售占比
```

模型参数进入记录器前先规范化和校验。缺失意图等同于 `AUTO`；`NONE` 抑制图表；无效类型或当前业务结果不具备的指标回退到该业务结果的默认值。

展示意图不是可信数据，因此它只能选择白名单类型和已存在字段，不能提供维度值、指标值、标题模板或任意前端选项。

### 3. 复用请求级记录器，不建立新的编排层

扩展现有 `ToolResultRecorder`，按同一 `traceId` 分别保存业务 `ToolResult` 和展示意图，并让现有 `clear` 同时清除两者。这样保留当前并发隔离和取消清理行为，避免增加只服务于一个调用点的 TurnContext/Planner 抽象。

系统提示词明确要求：展示意图 Tool 不能替代销售 Tool；仅在用户表达展示偏好时调用一次。若模型重复提供展示意图，记录器保留最后一个通过校验的值。

### 4. ChartCompiler 保留业务数据适配，只把展示选择参数化

`ChartCompiler` 继续按业务 Tool 类型把 DTO 转换成可信的维度和行数据，因为这些字段映射本身属于业务结果适配。编译入口增加可空展示意图：

```text
compile(toolResult, presentationIntent)
→ 选择默认维度和指标
→ 应用合法的 chartType / metric 覆盖
→ 生成并校验现有 ChartSpec
```

图表类型不再由业务 Tool 唯一决定，但字段和值仍完全来自 ToolResult。前端适配器和 ChartSpec 版本无需变化。

### 5. 保持现有完成门禁

`ChatService` 在模型流结束后同时读取业务结果和展示意图。业务结果为空时继续执行原有防伪造门禁；结果非空且意图不是 `NONE` 时生成至多一个 `chart`，随后发送 `done`。错误或取消时沿用现有清理逻辑。

## Risks / Trade-offs

- [模型没有调用展示意图 Tool] → 使用默认图表保证回答可完成，并通过系统提示词、契约测试和真实模型冒烟测试提高显式意图命中率。
- [用户要求的指标不在本次数据中] → 回退到默认指标，不让模型构造缺失数据。
- [饼图用于较多分类时可读性较差] → 明确请求优先；本次不增加主观图表推荐规则。
- [展示 Tool 与业务 Tool 并行或顺序变化] → 两者只按 `traceId` 独立记录，在流完成后统一读取。

## Migration Plan

1. 先增加展示意图记录和编译器覆盖能力，保持缺失意图时的旧行为。
2. 注册展示意图 Tool 并更新系统提示词。
3. 更新聊天收口和测试，确认旧问题仍产生原默认图表。
4. 使用两个已配置模型分别验证显式饼图、柱状图和无图请求。

回滚时移除展示意图 Tool，并让 `ChatService` 恢复调用原单参数编译入口；现有 SSE 和前端无需回滚。
